# MiniOMS Contracts

**Status: frozen (Week 3).** These are the messages and APIs that the services and the UI agree on.
Change them only on purpose, and update the UI's `types.ts` at the same time.

---

## 1. Rules

| Topic | Rule |
|---|---|
| **Field casing** | REST and SignalR use **camelCase** (`clOrdID`, `filledQuantity`). Redis uses **PascalCase** (`ClOrdID`). Only the first letter changes: `ClOrdID` → `clOrdID`. |
| **IDs** | `clOrdID`, `commandId` and `execID` are GUID strings. **The UI generates `clOrdID`** (it's the idempotency key: a repeat is rejected, not doubled). |
| **Enums** | Sent as **text** (`"Buy"`), never as numbers. |
| **Numbers** | Prices are decimals (`100.05`). Quantities are integers. |
| **Times** | ISO 8601 in **UTC**, ending in `Z` (`2026-10-04T14:40:36.5694118Z`). The UI converts to local time for display only. |
| **Sequence** | Every event has `sequence`, a single, always-increasing number from the OMS. Ignore an event whose `sequence` is lower than the latest one already seen for that order. |
| **Ports** | WebApi: `http://localhost:5244` (local, Visual Studio) and `http://localhost:8080` (Docker). |

---

## 2. Enums

| Enum | Values |
|---|---|
| `Side` | `Buy`, `Sell` |
| `OrderType` | `Limit`, `Market` |
| `OrderStatus` | `New`, `Acknowledged`, `PartiallyFilled`, `Filled`, `Cancelled`, `Rejected` |

- **Terminal statuses** (nothing changes after these): `Filled`, `Cancelled`, `Rejected`.
- **UI-only statuses** (never sent by the server): `Pending` (command sent, no event yet) and `Unconfirmed` (no event after 5 seconds).

**Symbols:** `ACME` (reference price 100.00), `BOLT` (50.00), `CRUX` (25.00). The tick size is 0.01 for all.

## 3. REST endpoints

| Method | URL | Request body | Success | Errors |
|---|---|---|---|---|
| `POST` | `/api/orders` | PlaceOrderRequest | **202** + CommandAccepted | **400** if `clOrdID` is empty, `symbol` is blank, or the JSON is invalid |
| `DELETE` | `/api/orders/{clOrdID}` | none | **202** + CommandAccepted | **404** if `clOrdID` isn't a GUID |
| `GET` | `/api/orders` | none | **200** + `OrderUpdated[]` (latest snapshot of every order) | |
| `GET` | `/api/positions` | none | **200** + `PositionUpdated[]` (latest snapshot of every position) | |

**202 means "received", not "done".** The result arrives later as SignalR events. Business errors (risk, unknown order and so on) **never** come back from REST; they arrive as `OrderUpdated` (Rejected), `RiskAlert` or `CommandRejected` events.

**PlaceOrderRequest**

| Field | Type | Notes |
|---|---|---|
| `clOrdID` | GUID string | Generated by the UI. Must be new for every order |
| `symbol` | string | `ACME`, `BOLT` or `CRUX` |
| `side` | `Side` | |
| `orderType` | `OrderType` | |
| `quantity` | integer | 1 to 1,000 (checked by risk, not by the API) |
| `limitPrice` | decimal or `null` | Required for `Limit` (on a 0.01 tick, within ±5% of the reference price). `null` for `Market` |

```json
{ "clOrdID": "3f2b8c1e-5a4d-4e8b-9c7a-1d2e3f4a5b6c", "symbol": "ACME", "side": "Buy", "orderType": "Limit", "quantity": 100, "limitPrice": 100.05 }
```

**CommandAccepted** (the 202 body)

| Field | Type |
|---|---|
| `clOrdID` | GUID string |
| `commandId` | GUID string (generated by the server) |

```json
{ "clOrdID": "3f2b8c1e-5a4d-4e8b-9c7a-1d2e3f4a5b6c", "commandId": "8a1c2d3e-4f5a-4b6c-8d7e-9f0a1b2c3d4e" }
```

**Snapshots (`GET`)** contain the event fields in section 5, including `sequence` and `timestampUtc`, but **no `eventType`**.

## 4. SignalR

**Hub URL:** `/hubs/orders` (local `http://localhost:5244/hubs/orders`, Docker `http://localhost:8080/hubs/orders`)

The server calls these methods on **every** client. The client never calls the server. Payloads use camelCase and contain the fields in section 5 (no `eventType`, because the method name already tells you the type).

| Method | Payload | When |
|---|---|---|
| `OrderUpdated` | OrderUpdated | Any order status or fill change |
| `PositionUpdated` | PositionUpdated | After a fill changes a position |
| `RiskAlert` | RiskAlert | A pre-trade risk rule rejected an order |
| `CommandRejected` | CommandRejected | Duplicate `clOrdID`, unknown `clOrdID`, or a cancel on a finished order |

**Method names must match exactly.** A typo is silently ignored, with no error.

**After connecting or reconnecting,** reload `GET /api/orders` and `GET /api/positions`, because events sent while disconnected are **not** replayed.

## 5. Events

Every event has:

| Field | Type | Meaning |
|---|---|---|
| `sequence` | integer | Always increasing, one counter across all events |
| `timestampUtc` | UTC time string | When the OMS created the event |

### OrderUpdated: the latest state of one order

| Field | Type | Meaning |
|---|---|---|
| `clOrdID` | GUID string | Which order |
| `symbol` | string | |
| `side` | `Side` | |
| `orderType` | `OrderType` | |
| `quantity` | integer | Original order quantity |
| `limitPrice` | decimal or `null` | `null` for market orders |
| `status` | `OrderStatus` | |
| `filledQuantity` | integer | Total filled so far |
| `avgFillPrice` | decimal | Weighted average fill price (0 if nothing filled) |
| `reason` | string or `null` | Why it was rejected or cancelled, if any |

```json
{ "clOrdID": "3f2b8c1e-5a4d-4e8b-9c7a-1d2e3f4a5b6c", "symbol": "ACME", "side": "Buy", "orderType": "Limit", "quantity": 100, "limitPrice": 100.05, "status": "Filled", "filledQuantity": 100, "avgFillPrice": 100.05, "reason": null, "sequence": 3, "timestampUtc": "2026-10-04T09:09:22.5943106Z" }
```

A typical sequence for one order: `New` → `Acknowledged` → (`PartiallyFilled`) → `Filled`. The other endings are `Cancelled` and `Rejected`.

### PositionUpdated: one symbol's position

| Field | Type | Meaning |
|---|---|---|
| `symbol` | string | |
| `quantity` | integer | Signed: + long, − short, 0 flat |
| `avgPrice` | decimal | Average price of the open position (0 when flat) |
| `realizedPnl` | decimal | Profit or loss locked in by closing trades |

```json
{ "symbol": "ACME", "quantity": 100, "avgPrice": 100.05, "realizedPnl": 0, "sequence": 4, "timestampUtc": "2026-10-04T09:09:22.5951951Z" }
```

### RiskAlert: an order failed a pre-trade risk rule

Always comes together with an `OrderUpdated` with status `Rejected` for the same `clOrdID`.

| Field | Type | Meaning |
|---|---|---|
| `clOrdID` | GUID string | The rejected order |
| `rule` | string | `UnknownSymbol`, `InvalidQuantity`, `InvalidPrice`, `InvalidTick`, `MaxOrderQuantity`, `PriceBand` or `MaxPosition` |
| `message` | string | Human-readable, for example `Price 200.05 is outside ±5% of reference 100.00` |

### CommandRejected: a command couldn't be applied

| Field | Type | Meaning |
|---|---|---|
| `commandId` | GUID string | The command that was rejected |
| `clOrdID` | GUID string | The order it was about |
| `reason` | string | `Duplicate ClOrdID`, `Unknown ClOrdID`, or `Order is already <Status>` |

## 6. Redis (backend only)

The UI never talks to Redis. This section is for the services.

| Key | Type | Purpose |
|---|---|---|
| `minioms:commands` | pub/sub channel | WebApi → OMS: `PlaceOrder`, `CancelOrder` |
| `minioms:events` | pub/sub channel | OMS → WebApi: all events |
| `minioms:orders` | hash (`ClOrdID` → JSON) | Latest `OrderUpdated` per order |
| `minioms:positions` | hash (`Symbol` → JSON) | Latest `PositionUpdated` per symbol |

- Messages on the channels are PascalCase JSON with a **type label as the first field**: `"CommandType"` (`PlaceOrder` / `CancelOrder`) or `"EventType"` (`OrderUpdated` / `PositionUpdated` / `RiskAlert` / `CommandRejected`).
- Pub/sub is **fire-and-forget**: a message sent while nobody is listening is lost.
- The OMS **saves the snapshot before publishing** the event.

```json
{"CommandType":"PlaceOrder","CommandId":"11111111-1111-1111-1111-111111111111","ClOrdID":"22222222-2222-2222-2222-222222222222","Symbol":"ACME","Side":"Buy","OrderType":"Limit","Quantity":100,"LimitPrice":100.05}
```
